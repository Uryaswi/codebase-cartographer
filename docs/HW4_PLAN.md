## Block 4 — Part 3: Change coupling with strict TDD (2 hr)

**Kickoff prompt (once):**
> We're building PRD feature F3 (change coupling) with STRICT TDD, following
> the TDD rules in CLAUDE.md. Work one acceptance criterion at a time. I
> will tell you which step (RED, GREEN, REFACTOR) we are on. Never write
> implementation during RED, and never edit tests during GREEN. Read F3 in
> @docs/PRD.md now and confirm the signature you'll target:
> `analyze_coupling(commits, *, min_shared=3, min_degree=30,
> max_changeset_size=30, exclude=()) -> list[CouplingResult]`.

**Tip for AC1–AC3:** the defaults `min_shared=3, min_degree=30` will filter out
small test cases. In early tests, pass `min_shared=1, min_degree=0` explicitly.
Tell Claude this if it forgets.

### The loop (repeat for each AC)

**RED**
> RED for AC<n>: write ONLY failing tests for AC<n> in
> tests/unit/test_coupling.py. Run pytest and show me the failure output.
> Do not touch implementation files.

Verify it actually fails (ImportError/AttributeError is OK for the very first
RED; after that, prefer assertion failures). Save one red output screenshot.
```bash
git add . && git commit -m "test(coupling): RED - AC<n> <short description>"
```

**GREEN**
> GREEN for AC<n>: write the minimum implementation in
> cartographer/analysis/coupling.py to make all tests pass. Do not modify
> any tests. Run pytest.
```bash
git add . && git commit -m "feat(coupling): GREEN - AC<n> <short description>"
```

**REFACTOR**
> REFACTOR: improve readability and structure of coupling.py and the tests
> (e.g. extract helpers, better names, test fixtures) without changing
> behavior. Run pytest and confirm it's still green.
```bash
git add . && git commit -m "refactor(coupling): <what you changed>"
```
If there's honestly nothing to refactor, skip the commit and say so in the
log annotation. Don't make fake changes.

### Suggested commit messages
| AC | RED | GREEN | Likely REFACTOR |
|---|---|---|---|
| 1 | count unordered file pairs per commit | pair counting with sorted keys | extract `make_commit` test helper |
| 2 | coupling degree from shared and revisions | integer degree formula | extract `_count_revisions` |
| 3 | ignore commits above max changeset size | filter large commits | move filtering to `_eligible_commits` |
| 4 | thresholds and deterministic ordering | apply min_shared/min_degree and sort | named sort key function |
| 5 | exclude globs before size check | fnmatch exclusions | combine filters into pipeline |
| 6 | flag cross-module pairs | top-level directory comparison | `_module_of(path)` helper |

**[MIN]** If you're short on time, do AC1–AC4 fully (12 commits) and do AC5–AC6
as RED+GREEN only.

- Take a break once: quit Claude Code, then resume with `claude --continue`

### Finish the feature (normal commit, not TDD-critical)
